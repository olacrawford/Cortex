# AGENTS.md

## What this is
Cortex — a Claude Code-style terminal AI coding assistant, written in Java. Phase-01 (multi-protocol LLM terminal chat client), phase-02 (tool system), phase-03 (Agent Loop: multi-round ReAct, batched concurrent execution, Plan Mode), phase-04 (system prompt engineering: modular assembly, env info, cache channels, system-reminder), phase-05 (permission system: 5-layer defense, human-in-the-loop approval, 3-tier YAML rules), phase-06 (MCP client: config-driven server discovery, stdio + Streamable HTTP transports, tool adaptation with mcp__server__tool namespaces), phase-07 (context management: two-layer compaction — tool-result offload + LLM summary/recovery, manual `/compact`, PTL emergency retry, token estimation, circuit breaker), phase-08 (project memory & session persistence: 3-tier MEWCODE.md with @include, JSONL session archive, /resume, auto notes), phase-09 (slash command system: 12 builtin commands in a startup-validated registry, Ui abstraction, autocomplete menu), phase-10 (skill system: SkillCatalog two-tier scan + hot reload, SkillExecutor inline/fork, skills as `[skill]`-marked PROMPT commands with $ARGUMENTS, install_skill remote installer), phase-11 (hook system: permission matcher extended to exact/not/regex/glob, 11 lifecycle events dispatched through HookEngine, 4 action types with shell/http blocking conventions, declarative hooks.yaml) and phase-12 (SubAgent mechanism: `subagent.Catalog` three-tier agent definitions with YAML frontmatter, unified Agent tool with defined/fork paths, `Agent.runToCompletion`, `task.Manager` background tasks with TaskList/TaskGet/TaskStop/SendMessage tools, multi-layer tool filtering, fork boilerplate nesting gates, `<task-notification>` reminder injection, sub-agent approval forwarding to the main TUI) and phase-13 (Worktree isolation: `worktree` package with slug validation / WorktreeManager lifecycle / quick-restore / post-creation setup, ToolContext explicit cwd threaded through the 6 core tools, `Definition.isolation: worktree` + AgentWorktreeRunner with `<worktree-context>` notice and autoCleanup, `/worktree` slash command, stale sweep) are implemented on `feature/phase13`. Next spec phases go under `docs/spec/`.

## Commands
- Build fat jar: `./gradlew shadowJar` → `build/libs/cortex.jar` (main class `com.cortex.Cortex`)
- Run: `java -jar build/libs/cortex.jar` (needs a JDK 21 `java`; see Gotchas)
- Test everything: `./gradlew test`
- One test class: `./gradlew test --tests '*RegistryTest'`
- Compile only: `./gradlew compileJava`

## Gotchas
- **JDK**: `gradle.properties` hardcodes `org.gradle.java.home` to a specific Temurin 21 path. The JDK toolchain is 21, but the machine's default `java` is 17 — use the Gradle wrapper (`./gradlew`), not a bare JDK; to run the jar use `/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home/bin/java`.
- **Config**: real keys live in `.cortex/config.yaml` (gitignored). Copy `.cortex/config.yaml.example` and fill in. Permission rules live in 3-tier settings files (user `~/.cortex/settings.yaml`, project `.cortex/settings.yaml`, local `.cortex/settings.local.yaml` — local is gitignored). Do not print `api_key` anywhere (spec N6/N7).
- **Protocol → client mapping** (`LlmClient.create`): `anthropic` → `AnthropicClient`; **`openai` AND `openai-compat` both → `OpenAiClient`**. `openai-compat` merely sets custom `base_url`. The separate `OpenAiCompatClient` in old plans does not exist — trust the code.
- **JLine keymap**: for printable input to reach the app, the keymap needs BOTH `setUnicode` (codepoints ≥ 256) AND `setNomatch` (Latin-1 chars) — an unbound ASCII char otherwise gets silently discarded by `BindingReader` (fixed in `Program.buildKeyMap`).
- **TUI rendering invariants** (`tui/tea/Program`): `clearView` must cursor-up `linesRendered - 1` (cursor sits at the end of the last view row); `CortexModel.onStreamTick` must return mid-turn collected `Command.println`s together with the next tick, otherwise committed tool lines get dropped.
- **Agent termination invariant**: `Agent.run`'s virtual thread ALWAYS enqueues `AgentEvent.Done` in a `finally` block (bypassing the cancel-checked `emit`) — the TUI relies on it to leave the streaming state on every path, including user cancel.
- **Cancelled rounds still feed history**: `Agent.executeBatched` fills unexecuted calls with a `（已取消。）` placeholder result and `conv.addToolResults` runs unconditionally, then `ensureAssistantTail` guarantees the history ends with an assistant text turn — otherwise the next request 400s on dangling tool_use / role alternation.
- **Permission Ask blocks the agent thread**: when the engine returns ASK, `Agent.requestApproval` blocks on `respond.take()` until the TUI (or a test) offers an `Outcome`. In tests without a UI, `drain()` auto-offers DENY_ONCE — otherwise the test hangs forever.

## Architecture (phase-09)
- `com.cortex.command` — slash command system. `Command` record (name/aliases/description/`Kind`/hidden/`Handler`) + `CommandRegistry` (name+alias → command index; duplicate key throws `IllegalStateException` at startup; `visible()` sorted by name for /help & menu; `prefixMatch` matches names only, never aliases/descriptions). `Dispatch.parse` returns `Parsed(name, isSlash)`: non-slash → `("",false)`; bare `/` or trailing args → `("",true)` so lookup misses. `Ui` interface is the only channel handlers may use (println/error/setMode/injectAndSend/queries/quit/forceCompact/openResumeMenu/clearAndNewSession/idle); `NopUi` is the test stub.
- **12 builtins** registered by `Builtins.registerAll` in `CortexModel`'s constructor: LOCAL `/help /status /memory /permission /session` (no history, no LLM, runnable any state), UI `/exit /plan /compact /resume /clear` (idle-gated), PROMPT `/do /review` (idle-gated; append fixed user text + start turn via `injectAndSend`). Idle guard for UI/PROMPT lives in `CortexModel.dispatchSlash`, not in handlers.
- **Dispatch flow**: `submit()` → strip → empty early-return → `Dispatch.parse` → non-slash = normal turn → `dispatchSlash`: lookup miss → "未知命令…" hint; handler exceptions → `✖` error line; handler UI calls buffer `Command`s into `cmdOutputs` (plus `cmdStartTurn` flag) which dispatchSlash returns as one `Command.batch`.
- `tui.CompletionMenu` — active when input starts with `/` (multi-line input closes it); ↑/↓ move highlight, Enter/Tab execute selection (sets input to `/<name>` then `submit()`), ESC closes keeping input, zero-match shows 无匹配 and Enter falls through to the unknown-command branch. Rendered inline in `renderChat` between input row and bottom separator; MAX_ROWS=8 with `↑/↓ N more` scroll hints. Key interception sits in `onKey` before the main key switch and only when CHAT+idle.
- `/clear` = close old `Writer` → `SessionContext.create` → `Writer.create` → rebuild `ConversationManager` hooked to new writer → `SessionRuntime.resetForNewSession` (resets replacement/recovery/autoTracking/anchor/turnCount, keeps contextWindow) → zero iter/usage → clear scrollback. State classes gained `reset()` (`ContentReplacementState`, `AutoCompactTrackingState`, `Recovery.RecoveryState`).
- Old `tui.Commands` dispatcher and its `AVAILABLE_HINT` are deleted; `/help`, the unknown-command hint and the ready hint ("就绪。输入 /help 查看可用命令。") all derive from the registry (N7). `Program.buildKeyMap` sets `setAmbiguousTimeout(150)` — bare ESC otherwise waits JLine's 1000ms default before firing (affects approval/resume/menu ESC alike).
- Name clash gotcha: `com.cortex.command.Command` vs `com.cortex.tui.tea.Command` — inside `CortexModel` the tea one is the single-type import; the command-package one must be fully qualified.
- Phase-08 health check (done alongside): `shadowJar` + full `test` green; JSONL archive, /resume, memory notes, /compact marker paths re-exercised end-to-end in tmux.

## Architecture (phase-10)
- `com.cortex.skill` — skill system. `SkillCatalog`: two-tier scan (user `~/.cortex/skills/` then project `.cortex/skills/`, project overrides by name, LinkedHashMap order); per-dir load prefers `skill.yaml + prompt.md` (phase-1 reads meta only, `bodyLoaded=false`) else `SKILL.md` (optional YAML frontmatter; bad YAML degrades to no-frontmatter; description falls back to first non-title body line; name defaults to dir name lowercased with spaces→`-`; `context: fork` is legacy compat for `mode`); `getFull` re-reads the body on every call for hot reload, keeping the old body on read failure. Single-skill parse failures never abort the tier (N1). Also `validateTools(registry)` → offending skill names (main prunes + warns) and `buildActiveContext(Set)` → `## Active Skills` section.
- `SkillExecutor` (all static): `executeInline` = assertAllowedToolsExist (IllegalStateException, N5) → `substituteArguments` (`$ARGUMENTS` replace / append `## User Request`) → `host.activateSkill` → `host.setToolFilter` (inline filter is recorded but NOT applied — plan decision, permission engine covers safety); `executeFork` = validate → render → `buildForkSeed` (full / recent≤5 / none) → `SkillForkHost.runSubAgent` (programmatic only; slash-triggered fork skills print a notice instead). `SkillHost`/`SkillForkHost` interfaces keep the skill package free of agent/tui imports (N4).
- Wiring: `Cortex.main` loads the catalog, prunes invalid allowed_tools, registers `InstallSkillTool`; `CortexModel` (implements `SkillHost`) calls `wireSkillsToAgent()` at the end of `activate()` — each skill becomes a PROMPT command whose description ends with `[skill]` (name conflicts with existing commands are skipped). `dispatchSlash` routes `[skill]`-marked commands itself: split `/name args…` from the raw input (Dispatch.parse returns empty name for argful input, so the split is a fallback after exact lookup misses), then `executeSkillCommand` → `getFull` → inline render → `injectAndSend` + `skill(<name>) Successfully loaded skill` notice. Non-skill commands with args keep the phase-9 unknown-command behavior. `/skills` (13th builtin) lists `ui.skillNames()`.
- `SkillInstaller.install(Fetcher, RepoRef, installRoot)`: parses skills.sh / github tree / raw SKILL.md URLs, walks GitHub Contents API recursively (limits: 1 MiB/file, 8 MiB total, 64 files, depth 4), stages into a sibling tempdir, requires SKILL.md, atomic `Files.move`. Fetcher is injectable (tests use stubbed maps). `InstallSkillTool` (`install_skill`, readOnly=false → EXEC Ask) reloads the catalog and invokes the `onInstalled` callback (`model::wireSkillsToAgent`) so new skills get slash commands without restart.
- Gotcha: Writer.onReplace (compaction) re-appends the whole post-compact message list after the compact marker — JSONL therefore contains repeated user lines; count distinct content, not line count, when checking injections in E2E.

## Architecture (phase-11)
- `com.cortex.permission.Matcher` — sealed interface with ExactMatcher / GlobMatcher / RegexMatcher / NotMatcher records; `Matchers.compile(pattern, isCommand)` parses `=value` / `~regex` / `!inner` / bare-glob prefixes and throws `Matchers.MatcherCompileException` at load time; compiled Patterns are cached statically (F15). `Rule.parse` now throws `Rule.RuleParseException` (Settings.toRuleSet prints `rule "..." parse failed: ...` to stderr and skips — no more silent drop, F4); `Rule.matches(target, isCommand)` is the match entry; `Rule.matchPattern` kept for compat (deprecated). Old configs keep working (bare glob unchanged).
- `com.cortex.hook` — `Event` (11 values, `isBlocking()` only for PRE_TOOL_USE / USER_PROMPT_SUBMIT), `Condition`/`AtomCondition` (all_of/any_of mutually exclusive at top level), `Action` sealed (Shell/Prompt/Http/Subagent), `HookRule`, `Payload` (TreeMap JSON — keys sorted, N6; `getByPath` dotted access missing→""). `HookLoader.load(projectRoot)` merges `~/.cortex/hooks.yaml` + `<root>/.cortex/hooks.yaml` (project loads first; duplicate names skip the later tier); every load error prints `hook "<name>": ... skipped` to stderr and continues (N1/N9). Blocking-event + async rules are rejected at load (F28).
- `HookEngine.dispatch(event, payload, cancel)` runs matching rules in declaration order: async rules start a virtual thread and never block/inject; sync results map to blocked (only on isBlocking events), prompt (appended to runtime pendingReminders), or error (stderr `[hook <name>] <event> failed: ...`, dispatch continues). only_once tracking lives in the engine's onceFired set; `resetForNewSession()` clears it (called from SessionRuntime.resetForNewSession).
- `HookExecutor`: shell runs `sh -c` with single-line sorted-JSON payload on stdin (broken-pipe on write ignored — commands like `echo` exit before reading), drains stdout/stderr on virtual threads, forwards hook stderr to the app stderr, exit 2 + blocking = blocked with stderr‖stdout as reason, other non-zero = failure; http block convention = 2xx + `{"decision":"block","reason":…}`; `${field}` body templates; subagent prints `[hook subagent] not yet implemented, skipped: <name>` (N8).
- Agent emit points (all via `dispatchHook`, engine from `runtime.hookEngine`): PRE_USER_MESSAGE (in streamOnce before provider.stream; hook reminders concatenated after the plan reminder in the same request, consumed via `runtime.takeReminders()`), PRE/POST_TOOL_USE (executeSingle before permission check / before PhaseEnd emit, plus per-call in executeReadOnlyBatch; blocked PreToolUse feeds `[hook <name>] <reason>` as an error tool_result and skips permission+execution, PhaseStart/PhaseEnd still emitted), PRE/POST_COMPACT (auto in roundRequest, emergency in emergencyCompact, manual in runForceCompact), STOP (natural completion only, before Done), NOTIFICATION (before Approval publishes and on Failed paths).
- TUI: UserPromptSubmit dispatch happens in `submit()` before the message is written — blocked keeps the input in the box and prints `[hook <name>] <reason>`; SessionStart fires at the end of `activate()`, SessionEnd before /clear teardown, /resume switch and /exit (plus a main() fallback after program.run()); SessionResume after a successful doResumeSession. `/hooks` (14th builtin) prints rules grouped by event with [once]/[async] flags and `Loaded from:` sources; `Ui.hookLines()/hookSources()` feed it.
- Gotcha: compaction replay (Writer.onReplace) re-appends all post-compact messages to the session JSONL — verify hook injections by content, not by JSONL line count.

## Architecture (phase-12)
- `com.cortex.subagent` — agent definitions. `Definition` record (name/description/tools/disallowedTools/model/maxTurns/permissionMode/dontAsk/background/systemPrompt/filePath/source; `isFork()` = name `__fork__`) parsed by `Parser` from `---`-frontmatter Markdown (name regex `^[A-Za-z][A-Za-z0-9_-]{0,31}$`; missing name/description or unclosed frontmatter → `ParserException`; bad model/permissionMode/maxTurns → stderr warning + fallback, file still loads — AC22; `dontAsk` maps to the boolean, not `Mode`). `Catalog.load(root)` merges builtin classpath resources (`src/main/resources/subagent/builtin/{general-purpose,explore,plan}.md`, missing/invalid builtin = RuntimeException fail-fast N4) → `~/.cortex/agents/*.md` → `<root>/.cortex/agents/*.md`, later tier overwrites by name (resolve is case-insensitive); `forkDefinition()` returns the empty-prompt, empty-filter `__fork__` def. `Catalog implements agent.AgentCatalogPort` (port interface breaks the agent↔subagent/task cycles).
- `com.cortex.tool.Filter` — `applyAgentToolFilter(FilterParams(all, source, background, fork, allowed, disallowed))` applies F30 order: strip `ALL_AGENT_DISALLOWED_TOOLS`（=["Agent"]）→ custom-source strip (empty, reserved) → background whitelist intersection (`ASYNC_AGENT_ALLOWED_TOOLS` = read_file/write_file/edit_file/glob/grep/bash/install_skill + `mcp__`-prefixed) → def blacklist → def whitelist. **Fork skips ① and ③**: its tool set must equal the parent's verbatim for prompt-cache hits (N2), so it still *sees* the Agent tool — nesting is blocked at execution instead (AC5).
- `com.cortex.agent` — `Agent` gained a `Builder` (`Agent.builder(client, registry, version, engine, runtime)`; existing constructors unchanged): systemPrompt (empty/null = inherit main system prompt), maxTurns (0 = 25), permissionMode(+set flag), dontAsk, approvalUpgrader, allowedTools (empty = no narrowing), forkContext. `runToCompletion(cancel, conv, task, events)` runs the same `roundRequest/streamOnce/executeBatched/emergencyCompact/hook` machinery as `loop` with a bounded turn count, plan-reminder-free reminder, no memory update, null-safe event bus; returns the final assistant text, throws `MaxTurnsReachedException` (carries last text) / `CancellationException` / RuntimeException on stream failure. Tool-allowlist is enforced twice: request `defs` are filtered (`definitionsFor`) and execution is gated (`toolAllowed` → error ToolResult on hallucinated calls). `executeSingle`'s ASK branch short-circuits to auto-allow when `dontAsk`; `requestApproval` consults `approvalUpgrader` first (present Outcome wins, empty falls through to the emit path) and registers `cancel.onCancel(DENY_ONCE)` so TaskStop can unblock an approval-blocked sub-agent. `ThreadLocal<Agent> CURRENT_CALLER` is set around every `registry.execute` (`executeAsCaller`) — AgentTool reads it as the QuerySource nesting gate; `activeConv` exposes the conversation of the running turn (fork message source).
- `AgentTool` (name `Agent`, readOnly=false, `timeout()` > auto-background threshold) — resolves the def (empty subagent_type = fork), computes background = run_in_background || def.background (fork forced; if `enableSubAgentBackground=false` fork errors and explicit-background degrades to foreground sync — N6), filters tools, builds a sub-Agent on `SessionRuntime.empty(parent cw)` with the shared hookEngine, then either `taskMgr.launch` → `{"task_id":…,"status":"async_launched"}` or `startForeground` + `awaitCompletion(autoBackgroundMs())` → final text, else `{"task_id":…,"status":"timed_out_to_background"}`. `AUTO_BACKGROUND_MS`=120s, overridable via `-Dcortex.subagent.autoBackgroundMs=` (read per execute). `LaunchFork.launch(parent, seed, body, allowedTools, cancel)` is the shared skill-fork launcher (CortexModel implements `SkillForkHost` with it); skill-fork children get `forkContext=true`.
- `com.cortex.task` — `Manager implements TaskManagerPort`: `launch`/`startForeground` register a `BackgroundTask` (id `task_<hex>`, status/result/err/endTime/usage/toolCount/lastActivity, CountDownLatch) and run a virtual thread over `runToCompletion`; any Throwable → FAILED (N3); completion pushes the id onto `doneQueue` (LinkedBlockingQueue, cap 32, overflow → stderr). `stop` cancels the token; `sendMessage(name, msg)` requires COMPLETED, appends to the sub-conversation, resets to RUNNING and **spawns a fresh virtual thread** (calling inline would stall the SendMessage tool into its per-tool timeout). Tools `TaskList`(ro)/`TaskGet`(ro)/`TaskStop`/`SendMessage` return compact JSON; unknown ids are isError results. `setApprovalForwarder` is the F13 upgrader bridge.
- TUI: `CortexModel` takes the Manager + AgentTool (13-arg ctor), calls `agentTool.setParent(agent)` in `activate()` (provider re-selection refreshes it), starts `consumeTaskDone` virtual thread (doneQueue → `Tasks.buildTaskNotification` → `runtime.appendReminders` — model-only, N7), and implements SkillForkHost. **Approval queue invariant:** main-loop Approvals and forwarded sub-agent Approvals both enter `offerApproval` (pending slot + `approvalQueue` FIFO, `promoteNextApproval` after each verdict). Directly assigning `pending` from the event stream loses queued/foreign requests and deadlocks the sub-agent — this was a real E2E bug; keep every path going through the queue.
- Config: `AppConfig.enableSubAgentBackground` (`enable_sub_agent_background` key, null = true via `effectiveEnableSubAgentBackground()`); E2E: `/tmp/cortex12-e2e` + `-Dcortex.subagent.autoBackgroundMs=5000` for short auto-background runs.

## Architecture (phase-13)

## Architecture (phase-06)
- `com.cortex.mcp` — MCP client on official SDK `io.modelcontextprotocol.sdk:mcp:1.1.3` (sync sessions, `requestTimeout` = 30s). `McpConfigLoader.loadConfig(root)` merges 2-tier YAML (`~/.cortex/mcp.yaml` + `<root>/.cortex/mcp.yaml`, project overrides by server name), expands `${VAR}` in env/headers values only (undefined → "" + warn), skips invalid servers. `McpManager.start(cfg, version)` connects all servers concurrently on virtual threads (per-server failure isolated, 30s timeout); `McpTool.adaptTool` wraps remote tools as `mcp__<server>__<tool>` (skip names with chars outside `[A-Za-z0-9_-]`), readOnly strictly from `annotations.readOnlyHint==true`, protocol errors/timeouts → isError results. `close()` has a 5s total fallback. Config example: `docs/mcp/mcp-servers.example.yaml`.
- **MCP tools flow through the existing permission pipeline unchanged** (permission package zero-diff): friendlyName returns mcp names as-is (rules can write `mcp__server__*`), categorize puts readOnlyHint=true tools in READ (auto-allowed, concurrent) and others in EXEC (Ask), extractTarget returns not-a-file for unknown tools so blacklist/sandbox skip them.

## Architecture (phase-07)
- `com.cortex.compact` — context management sole authority. Layer 1 (`offloadAndSnip`) offloads tool results exceeding `SINGLE_RESULT_LIMIT` (50K bytes) / per-message `MESSAGE_AGGREGATE_LIMIT` (200K bytes) to `.cortex/sessions/<id>/tool-results/<toolUseId>`, replacing them in-conversation with a preview body (`buildPreview`, head ≤ 20 lines / 2048 bytes) and freezing the decision in `ContentReplacementState` (KEPT/REPLACED never flip; SKIP = spill failure → retry next round). Layer 2 (`autoCompact`/`forceCompact`/`runSummary`) calls the provider with tools empty to produce a 9-section `<summary>` (`SummaryPrompt`), appends a 3-part recovery attachment (`Recovery`: last-5 files snapshot, exact tool list, boundary notice) and a `pickRecentTail` recent-original tail (both token ≥ 10K and count ≥ 5), merged into a single user message to avoid user/user 400. Token estimation (`Token.estimateTokens`) anchors on the last real provider usage (`usageAnchor`), incremental chars ÷ 3.5.
- **SessionRuntime** (`com.cortex.agent`) — long-lived state held by the TUI model across `run` calls (the per-turn `new Agent(...)` would otherwise reset the decision ledger / circuit breaker / usage anchor / file tracking): `replacement`, `recovery`, `autoTracking`, `session`, `contextWindow`, `usageAnchor`/`anchorMsgLen`. `Agent` gains `.runtime`, a `runLock` (run vs `/compact` mutual exclusion), `streamOnce` throws `StreamException` on PTL, `recordReadFiles` (pure bytes, before `addToolResults`), emergency-compact + single retry (`emergencyRetried`), and `runForceCompact` for the TUI.
- **PTL sentinel** — `com.cortex.llm.PromptTooLongException` (RuntimeException, `isPromptTooLong` walks the cause chain for `prompt is too long` / `context_length` etc.). Both clients wrap a detected PTL into `StreamEvent.Error(msg, cause)`; the Agent's `streamOnce` throws `StreamException` whose cause is `PromptTooLongException`, triggering emergency compaction (auto path counts failures toward the `AutoCompactTrackingState` breaker; manual/emergency bypass it). Summary-request PTL goes through `ptlRetry` (drop 1 group × 3, then `ceil(0.2×remaining)` until it fits or is exhausted).
- **Config** — `ProviderConfig` adds `contextWindow` (+ `effectiveContextWindow()`; `ProtocolDefaults` = anthropic 200000 / openai 128000); auto threshold = `contextWindow − 20000 − 13000`. TUI commands moved to `com.cortex.tui.Commands` registry (`/exit /plan /do /compact`, unknown → friendly hint); auto/emergency compaction status events render as system notices (`CompactPhase` BEFORE/AFTER, `formatCompactNotice`), manual `/compact` result pushed back via `CompactNoticeMessage`.
- **Gotchas**: `SessionRuntime.empty(cw)` writes the session spill dir to a temp dir (tests). `Agent` 4-arg ctor still works (auto-creates empty runtime). Summary request uses `Request(msgs, List.of(), new SystemPrompt("",""), "")` — system/reminder empty.

## Architecture (phase-05)
- `com.cortex.permission` — 5-layer defense. `PermissionEngine.check(mode, call, readOnly)` runs layers ① blacklist (regex, unconfigurable, EXEC tools only) → ② sandbox (project-root prefix check AFTER symlink resolution; file tools only) → ③ rule engine (local > project > user tiers, deny-first within a tier, friendly names Bash/Read/Write/Edit/Glob/Grep) → ④ mode fallback matrix (READ always Allow; DEFAULT/PLAN: WRITE/EXEC Ask; ACCEPT_EDITS: WRITE Allow; BYPASS: all Allow). ASK = layer ⑤ human-in-the-loop, orchestrated by agent.
- `com.cortex.agent` — ReAct loop (`Agent.run(conv, mode, cancel)`); on ASK emits `AgentEvent.Approval(ApprovalRequest{respond})` and blocks on `respond.take()`; DENY (any layer) becomes a structured error ToolResult fed back to the model without interrupting the loop. `permission.Mode` {DEFAULT, ACCEPT_EDITS, PLAN, BYPASS} replaced agent.Mode (plan keeps read-only toolset + reminder).
- `com.cortex.tui` — approval menu state (`pending`/`approveCursor`): ↑↓+Enter, digits 1/2/3, y/n; Esc/Ctrl+C during approval offers DENY_ONCE then cancels the turn; Shift+Tab cycles mode (idle only); status bar left shows the current permission mode (provider name no longer shown).
- Local allow persistence: human-loop "永久" writes an exact-match rule to `.cortex/settings.local.yaml` (gitignored) and syncs the in-memory ruleset.
- Thinking is disabled for requests whose history contains tool turns (Anthropic would 400 without the original signed thinking blocks).
